# 0007. Native projects are generated, not committed

| | |
|---|---|
| **Status** | Proposed |
| **Date** | 2026-11-15 |
| **Ticket** | `FND-05` |
| **Requirements** | Spec §18.2 (development builds), roadmap §3.1 (Expo SDK 58, EAS Build) |

## Context

An Expo app can keep its `ios/` and `android/` folders in git and edit them by hand, or have `expo prebuild` generate them from the app config and config plugins each time (Expo calls this continuous native generation). FND-05 adds some thirty native libraries at once, and every later ticket that adds a permission, an entitlement or a native dependency has to change native configuration somewhere. That place has to be decided before the first such ticket.

Checked on SDK 58.0.25: every library in the smoke build either needs no native configuration or ships a config plugin. None needed a hand edit to a generated file.

## Decision

`apps/mobile/ios` and `apps/mobile/android` are generated by `expo prebuild` and ignored by git. Native configuration lives in `apps/mobile/app.config.ts` and in config plugins, and nowhere else.

## Alternatives considered

| Alternative | Why not |
|---|---|
| Commit `ios/` and `android/` and edit them by hand | Every SDK upgrade becomes a manual merge of the template's native changes, and two tickets touching `Podfile` or `build.gradle` conflict. EAS Build would also stop running prebuild, so local and cloud builds could drift. |
| Commit them, but regenerate on every change | The diff of a regenerated project is large and unreviewable, and nothing stops a hand edit from slipping in and being lost at the next regeneration. |

## Consequences

- A change to native configuration is a change to `app.config.ts` or a config plugin, so it is reviewable in a few lines and applies to local and EAS builds alike.
- A local native build starts with `expo prebuild` (`expo run:ios` and `expo run:android` run it when the folder is missing). After changing the config or a native dependency, run `expo prebuild --clean`.
- A hand edit inside `ios/` or `android/` is lost at the next prebuild. Native configuration no existing plugin covers needs a small local config plugin under `apps/mobile/plugins/`, with its own ADR if it is more than a few lines.
- Revisit if a required native change can't be expressed as a config plugin, or if a library's plugin is abandoned.
